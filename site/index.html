What the framework is

An XCTest-style framework for iCloud-like services, plus the Python tooling above. The Swift part needs macOS and Xcode, so it cannot run here.

1

Retry with a budget

A test base class with exponential backoff that tells retryable errors from real ones, and a timeout budget per operation.

2

Break it on purpose

Deterministic fault injection for latency, 5xx and 429 responses, going offline and partial batch failures, with no real network.

3

Multi-device conflicts

A small DSL replays edits and syncs across devices in a fixed order and asserts how conflicts resolved.

Run it

The Swift package needs macOS with Xcode 15 or later. The Python scripts run anywhere.

swift build
swift test

python3 scripts/triage.py log build/xcodebuild.log
python3 scripts/triage.py categorize "HTTP 503"
python3 scripts/coverage_gap.py \
  --source Sources/ --tests Tests/ \
  --min-coverage 80 --show-gaps

The cloud client is a mock. The suite exercises the framework, not a real iCloud service.

What this does not do
  • The triage rules are regular expressions. A message none of them match comes back as unknown.
  • The log parser expects real XCTest "Test Case ... started/failed" lines. Other formats parse to zero failures.
  • It does not read .xcresult bundles in the browser. That path calls xcrun xcresulttool on a Mac.
